  • GitHub 계정: 앱을 인터넷에 올리는 무료 서비스입니다. 없으면 3단계에서 만듭니다.
  • 이 폴더: D:\Code\IT Calcul (앱 코드가 모두 들어 있습니다)
  • PC 1대 (Chrome 또는 Edge 브라우저)

진행하면서 아래 두 값을 메모장에 적어 두세요. 나중에 계속 씁니다.

화면 모양이나 메뉴 이름은 Google·GitHub가 업데이트하면 조금 달라질 수 있습니다. 비슷한 이름의 메뉴를 찾으면 됩니다.

1Google Sheets 만들기

시험 기록이 쌓일 스프레드시트를 하나 만듭니다.

  1. 브라우저에서 https://sheets.google.com 에 접속해 기록용 Google 계정으로 로그인합니다.
  2. + 빈 스프레드시트 (왼쪽 위의 큰 + 칸)를 누릅니다.
  3. 왼쪽 위 제목 없는 스프레드시트를 눌러 이름을 바꿉니다. 예) Diffusion Rate 기록
지금 보이는 화면: 빈 표 하나, 아래쪽 탭에 시트1. 시트는 2단계에서 자동으로 만들어지니 아무것도 입력하지 마세요.
팀원과 공유: 오른쪽 위 공유 → 팀원 이메일 입력 → 권한 선택(보기 전용이면 뷰어, 직접 고칠 사람은 편집자). 앱에서 저장하는 데는 공유가 필요 없습니다. 시트를 열어 보려는 사람에게만 주세요.
✅ 확인: 이름을 바꾼 빈 스프레드시트가 열려 있습니다.

2Apps Script 배포

앱이 보낸 기록을 시트에 적어 주는 작은 프로그램(서버)을 시트에 붙입니다.

2-1. 코드 붙여 넣기

  1. 1단계 스프레드시트에서 위쪽 메뉴 확장 프로그램 → Apps Script 를 누릅니다. 새 탭이 열립니다.
  2. 편집기 안의 기존 내용(function myFunction() {…})을 Ctrl+A 로 전부 선택하고 Delete 로 지웁니다.
  3. PC에서 D:\Code\IT Calcul\apps-script\Code.gs 파일을 메모장으로 엽니다 (파일 오른쪽 클릭 → 연결 프로그램 → 메모장).
  4. 메모장에서 Ctrl+A → Ctrl+C, Apps Script 편집기에 Ctrl+V 로 붙여 넣습니다.
  5. 위쪽 제목 없는 프로젝트를 눌러 이름을 Diffusion Rate 서버 로 바꿉니다.
  6. 💾 프로젝트 저장 아이콘(또는 Ctrl+S)을 누릅니다.

2-2. 처음 한 번 실행해 권한 주기

  1. 편집기 위쪽 도구 막대에서 함수 선택 칸(▶ 실행 버튼 오른쪽)을 눌러 setup 을 고릅니다.
  2. ▶ 실행 을 누릅니다.
  3. 승인 필요 창이 뜨면 권한 검토 → 기록용 Google 계정을 선택합니다.
  4. "Google에서 확인하지 않은 앱" 경고가 나오면, 왼쪽 아래 고급 → Diffusion Rate 서버(으)로 이동(안전하지 않음) 을 누릅니다.
    직접 만든 스크립트라서 Google 심사를 받지 않았다는 뜻입니다. 내 코드이므로 진행해도 됩니다. 요청하는 권한은 이 스프레드시트 보기·수정입니다.
  5. 허용 (또는 계속)을 누릅니다.
  6. 아래쪽 실행 로그에 실행이 완료되었습니다 가 나오면 성공입니다.
  7. 스프레드시트 탭으로 돌아가 보면 아래쪽에 시험기록, 변경이력, 설정 시트가 생겨 있습니다. 비어 있는 시트1은 지워도 됩니다 (탭 오른쪽 클릭 → 삭제).

2-3. 웹앱으로 배포

  1. Apps Script 편집기 오른쪽 위 파란 배포 → 새 배포 를 누릅니다.
  2. 왼쪽 유형 선택 옆 ⚙ 톱니 → 웹 앱 을 고릅니다.
  3. 아래와 같이 입력합니다.
    항목입력값
    설명v1
    다음 사용자 인증 정보로 실행나 (내 이메일)
    액세스 권한이 있는 사용자모든 사용자 ("Google 계정이 있는 모든 사용자"가 아님)
  4. 배포 를 누릅니다. 권한을 다시 물으면 2-2와 같이 허용합니다.
  5. 웹 앱 URL 아래 복사 를 눌러 메모장 ① 웹앱 URL 칸에 붙여 넣습니다.
    모양: https://script.google.com/macros/s/AKfy…긴 글자…/exec
  6. 완료 를 누릅니다.
"모든 사용자"인 이유: 앱에는 로그인이 없어서, 앱이 시트에 기록을 보내려면 이 설정이 필요합니다. 대신 웹앱 URL을 아는 사람은 누구나 시트에 기록을 보낼 수 있습니다. URL은 팀원에게만 메신저로 전하고, 공개 게시판·GitHub에는 올리지 마세요. 시트 자체(내용 보기)는 1단계의 공유 설정을 따르며 URL로 열리지 않습니다.
✅ 확인: 메모장에 …/exec 로 끝나는 웹앱 URL이 적혀 있습니다. 이 URL을 브라우저 주소창에 넣으면 {"ok":true,"app":"diffusion-rate",…} 같은 글자가 보입니다.

3앱 배포 (GitHub Pages)

앱 코드를 GitHub에 올리면 자동으로 테스트·빌드되어 무료 인터넷 주소가 생깁니다. 처음 한 번만 설정하면, 이후에는 코드를 올릴 때마다 자동으로 다시 배포됩니다.

3-1. GitHub 계정 만들기 (이미 있으면 건너뛰기)

  1. https://github.com/signup 에서 이메일·비밀번호·사용자 이름(영문)을 입력해 가입합니다.
  2. 사용자 이름을 메모해 두세요. 앱 주소에 들어갑니다. 예) hong-qa

3-2. GitHub Desktop 설치

명령어 없이 버튼으로 코드를 올리는 프로그램입니다.

  1. https://desktop.github.com 에서 Download for Windows 를 눌러 설치합니다.
  2. 실행 후 Sign in to GitHub.com → 브라우저에서 Authorize desktop 을 눌러 로그인합니다.
  3. 이름·이메일 확인 화면은 그대로 Finish 를 누릅니다.

3-3. 폴더를 저장소로 만들고 올리기

  1. GitHub Desktop 메뉴 File → Add local repository… 를 누릅니다.
  2. Choose… 로 D:\Code\IT Calcul 폴더를 고릅니다.
  3. "This directory does not appear to be a Git repository" 문구 아래 파란 글자 create a repository 를 누릅니다.
  4. 열린 창에서 Name·Local path는 그대로 두고, Git ignore·License는 None 으로 둔 채 Create repository 를 누릅니다.
    폴더 안의 .gitignore 파일 덕분에 용량이 큰 node_modules, dist 폴더는 자동으로 빠집니다.
  5. 왼쪽 Changes 탭에 파일 목록이 남아 있으면: 왼쪽 아래 Summary 칸에 첫 업로드 입력 → Commit to main. (목록이 비어 있으면 이미 저장된 것이니 건너뜁니다.)
  6. 위쪽 Publish repository 를 누릅니다.
  7. 창에서:
    • Name: diffusion-rate 로 바꿉니다 (영문 소문자·하이픈만).
    • Keep this code private: 체크 해제합니다. 무료 계정의 GitHub Pages는 공개 저장소에서만 됩니다.
    Publish repository 를 누릅니다.
공개 저장소에 올라가는 것: 앱 코드, 서버 코드(Code.gs), 요구정의서·이 가이드. 시험 기록과 웹앱 URL은 올라가지 않습니다 (기록은 Sheets에, URL은 각 기기 설정에만 있음). 요구정의서를 공개하고 싶지 않다면 Publish 전에 해당 HTML 파일을 다른 폴더로 옮기세요.

3-4. GitHub Pages 켜기

  1. GitHub Desktop 메뉴 Repository → View on GitHub 을 누르면 브라우저에 저장소 페이지가 열립니다.
  2. 위쪽 ⚙ Settings → 왼쪽 메뉴 Pages 를 누릅니다.
  3. Build and deployment → Source 를 GitHub Actions 로 바꿉니다 (저장 버튼 없이 바로 적용됩니다).
  4. 위쪽 ▶ Actions 탭을 누릅니다. Deploy to GitHub Pages 실행이 보입니다.
    • 🟡 노란 점: 진행 중입니다. 2~3분 기다립니다.
    • ❌ 빨간 X: Pages를 켜기 전에 실행돼서 실패한 것입니다. 그 줄을 눌러 들어가 오른쪽 위 Re-run all jobs 를 누릅니다.
    • ✅ 초록 체크: 완료입니다.
  5. ✅ 가 되면 Settings → Pages 위쪽에 Your site is live at … 주소가 나옵니다. 이것을 메모장 ② 앱 주소 칸에 적습니다.
    모양: https://사용자이름.github.io/diffusion-rate/
✅ 확인: ② 앱 주소를 브라우저에서 열면 파란 계산기 화면이 나옵니다. 처음 열 때 위쪽에 "오프라인에서도 쓸 수 있게 준비됐습니다"가 잠깐 뜹니다.

4Sheets 연결 확인

PC 한 대에서 먼저 연결하고, 기록 1건이 시트에 들어가는지 확인합니다.

  1. ② 앱 주소를 엽니다 → 아래쪽(또는 왼쪽) 메뉴 ⚙ 설정.
  2. Google Sheets 연결 칸에 ① 웹앱 URL을 붙여 넣고 연결 테스트 후 저장 을 누릅니다.
  3. ✓ 표시와 함께 상태: 연결됨 이 나오면 성공입니다.
  4. 같은 화면 습윤 용액 목록에서 쓰는 용액을 + 추가 로 등록합니다. 예) 물, IPA 60%. 이 목록은 시트의 설정 시트에 저장되어 다른 기기에도 똑같이 나타납니다.
  5. 🧮 계산 으로 가서 아래 샘플 값을 넣고 저장 합니다.
    체적 V시험 압력측정 시간 tΔP대기압결과
    500 mL1 bar5 min50 mbar기본값4.93 mL/min · 296.1 mL/hr
  6. 스프레드시트의 시험기록 시트를 새로고침(F5)하면 한 줄이 들어와 있습니다. 변경이력 시트에도 create 한 줄이 생깁니다.
  7. 확인이 끝나면 앱 🗂 최근 기록 에서 이 샘플을 삭제 합니다. 시트의 줄은 지워지지 않고 deleted 열이 TRUE 로 바뀝니다 (이력 보존).
✅ 확인: 시험기록 시트에 샘플 1줄, 앱 위쪽 배지가 대기 0건입니다.

5각 기기에 설치

기기마다 ① 앱 주소로 열고 → 홈 화면에 설치 → 설정에 웹앱 URL 붙여 넣기, 이 세 가지를 합니다.

주소 보내기 팁: ② 앱 주소와 ① 웹앱 URL을 카카오톡 "나와의 채팅"으로 보내 두면 휴대폰·태블릿에서 길게 눌러 복사할 수 있습니다. 카톡 안에서 바로 열지 말고 아래 브라우저로 여세요.

5-1. 현장 PC (Windows · Chrome 또는 Edge)

  1. Chrome(또는 Edge)에서 ② 앱 주소를 엽니다.
  2. 주소창 오른쪽 끝의 ⊕ 설치 아이콘(모니터+화살표 모양)을 누르고 → 설치.
    아이콘이 없으면: Chrome은 ⋮ 메뉴 → 전송, 저장, 공유 → 페이지를 앱으로 설치 / Edge는 … 메뉴 → 앱 → 이 사이트를 앱으로 설치.
  3. 바탕화면·시작 메뉴에 Diffusion Rate 아이콘이 생기고, 주소창 없는 창으로 열립니다.
  4. ⚙ 설정 → 웹앱 URL 붙여 넣기 → 연결 테스트 후 저장.

5-2. Android 휴대폰·태블릿 (Chrome)

  1. Chrome 앱에서 ② 앱 주소를 엽니다 (삼성 인터넷도 비슷합니다).
  2. 아래쪽에 "앱 설치" 안내가 뜨면 누릅니다. 안 뜨면 오른쪽 위 ⋮ → 앱 설치 (또는 홈 화면에 추가 → 설치).
  3. 홈 화면의 파란 아이콘으로 엽니다.
  4. ⚙ 설정 → 웹앱 URL 붙여 넣기 → 연결 테스트 후 저장.

5-3. iPhone·iPad (Safari)

  1. Safari 에서 ② 앱 주소를 엽니다.
  2. 아래쪽(iPad는 위쪽) 공유 ⬆︎ 버튼 → 목록을 내려 홈 화면에 추가 → 오른쪽 위 추가.
  3. 꼭 홈 화면 아이콘으로 엽니다. Safari에서 연 앱과 홈 화면 앱은 저장 공간이 따로라서 설정을 다시 해야 합니다.
  4. ⚙ 설정 → 웹앱 URL 붙여 넣기 → 연결 테스트 후 저장.
iPhone·iPad 주의: 앱이 꺼져 있을 때는 기록을 보내지 못합니다. 와이파이가 없는 곳에서 저장한 기록은 다음에 앱을 열 때 보내집니다. 위쪽 배지의 "대기 n건"이 0이 되는지 가끔 확인하세요.
✅ 기기별 확인: 설정 화면 상태: 연결됨, 습윤 용액 목록이 4단계에서 등록한 것과 같음. 기기마다 기기 ID가 달라서, 시트의 device_id 열로 어느 기기에서 저장했는지 알 수 있습니다.

6나중에 고칠 때

앱 화면·계산을 고쳤을 때

  1. GitHub Desktop을 엽니다. 왼쪽 Changes에 바뀐 파일이 보입니다.
  2. Summary에 무엇을 고쳤는지 한 줄 입력 → Commit to main → 위쪽 Push origin.
  3. GitHub Actions 탭에서 ✅ 가 되면(2~3분) 배포 끝입니다. 테스트가 실패하면 ❌ 가 되고 기존 앱은 그대로 유지됩니다.
  4. 각 기기에서 앱을 열면 위쪽에 "새 버전이 있습니다" 가 뜹니다 → 업데이트. 저장된 기록과 설정은 그대로입니다.

서버 코드(Code.gs)를 고쳤을 때

  1. Apps Script 편집기에 새 코드를 붙여 넣고 저장합니다.
  2. 배포 → 배포 관리 → 기존 배포를 고르고 ✎ 수정.
  3. 버전을 새 버전 으로 바꾸고 → 배포.
"새 배포"를 누르지 마세요. 새 배포를 만들면 웹앱 URL이 바뀌어 모든 기기에서 URL을 다시 붙여 넣어야 합니다. 꼭 배포 관리 → 수정 → 새 버전으로 하세요. URL이 그대로 유지됩니다.

7문제 해결

증상해결
연결 테스트 실패 / "URL 형식을 확인하세요"URL이 …/exec 로 끝나는지 확인합니다 (/dev 로 끝나는 테스트 주소는 안 됩니다). 앞뒤 공백도 지웁니다.
연결 테스트 실패 (URL은 맞음)2-3의 액세스 권한이 모든 사용자인지 확인합니다. 배포 관리 → 수정에서 바꾸고 새 버전으로 배포합니다.
앱 주소가 404Actions 탭에서 ✅ 인지 확인하고, Settings → Pages의 Source가 GitHub Actions인지 확인합니다. 처음 배포 후 몇 분 걸릴 수 있습니다.
Actions에 ❌ (Re-run 해도 실패)실패한 줄을 눌러 빨간 단계를 열고 오류 문구를 복사해 개발 담당(또는 Claude)에게 전달합니다.
배지에 "대기 n건"이 줄지 않음인터넷 연결을 확인하고 🗂 최근 기록 → 지금 동기화. 기록 옆 ⚠ 를 눌러 오류 내용을 확인합니다.
"서버가 바쁩니다"여러 기기가 동시에 저장한 경우입니다. 자동으로 다시 보내니 그대로 두면 됩니다.
설치 버튼이 안 보임iPhone은 Safari에서만 됩니다. 카톡·네이버 앱 안의 브라우저가 아니라 Chrome/Safari로 직접 엽니다.
기기를 바꾸거나 앱을 지웠음시트에 보낸 기록은 남아 있습니다. 새 기기에서 5단계만 다시 하면 됩니다. 단, 대기 중이던(아직 안 보낸) 기록은 사라지니 앱을 지우기 전에 대기 0건을 확인하세요.
기록을 찾거나 차트·엑셀이 필요함스프레드시트에서 합니다. 필터(데이터 → 필터 만들기), 차트(삽입 → 차트), 엑셀 받기(파일 → 다운로드 → .xlsx). deleted 열이 TRUE인 줄은 삭제한 기록입니다.
시트에서 직접 고치지 마세요: 시험기록 시트의 값을 손으로 바꾸면 앱의 기록과 달라집니다. 수정은 앱의 최근 기록 → 수정으로 하세요. 열 이름(1행)과 열 순서도 바꾸면 안 됩니다. 분석용 표가 필요하면 다른 시트를 만들어 거기서 참조하세요.
